# 06 - Responsive And Motion Behavior

**What to build:** Make the redesigned experience usable across desktop and mobile without compressing the desktop three-panel model into an unusable layout.

**Blocked by:** 02 - Workspace Stage Flow; 03 - Dashboard And Navigation; 04 - Canvas Symbols And Accessibility.

**Status:** complete

## Comments

- 2026-08-16: Responsive workspace, landing, catalog, account, Scenario, Review, and Canvas inspection layouts use responsive recomposition, touch-sized controls, persistent status messaging, keyboard focus, and reduced-motion CSS behavior.

- [ ] Desktop supports complex Canvas editing with the Canvas-first Design surface and contextual panel visible where space permits.
- [ ] Mobile fully supports Landing, Catalog, Challenge Detail, authentication, Practice Home, Clarify, Scenario responses, Review reading, account flows, and essential architecture inspection and edits.
- [ ] Mobile uses a compact top bar, bottom navigation, full-screen stage surfaces, and sheets rather than compressed desktop columns.
- [ ] Mobile clearly communicates when an action requires the desktop Canvas.
- [ ] Purposeful 160-220ms transitions cover focus changes, panel transitions, save states, Scenario pressure changes, and Review processing.
- [ ] Reduced-motion preferences remove or simplify non-essential transitions.
- [ ] Keyboard, touch, pointer, and screen-reader paths remain usable for all supported mobile and desktop actions.
- [ ] Save/sync status remains continuously visible and quota/errors remain localized with explicit recovery actions.
- [ ] Mobile landing preserves the desktop narrative in sequential stacked sections with reduced copy, large touch targets, and minimal navigation.
- [ ] Landing evidence artifacts use a mobile-specific vertical representation rather than a shrunken desktop composition.
- [ ] Mobile Challenge previews use editorial rows instead of dense grids or carousels.
