# 04 - Canvas Symbols And Accessibility

**What to build:** Make the Architecture Canvas feel like a reasoning instrument with semantic symbols, multiple creation paths, and a non-spatial access path.

**Blocked by:** 01 - Design Foundations And Brand; 02 - Workspace Stage Flow.

**Status:** complete

## Comments

- 2026-08-16: The Canvas editor provides labeled semantic component palette actions, non-drag connection creation, keyboard deletion, boundaries, undo/redo, autosave conflict recovery, contextual inspection, and accessible labels while preserving the visual Canvas as the spatial surface.

- [ ] Supported Components use consistent Lucide semantic icons, labels, and secondary family color cues.
- [ ] Component creation works through a labeled palette, searchable command menu, and direct manipulation.
- [ ] Essential Canvas actions have keyboard alternatives and are never drag-only.
- [ ] Design is Canvas-first with a compact palette/command search and one contextual inspector at a time.
- [ ] Connections support drag-to-connect and structured source/Intent/target creation without dragging.
- [ ] Boundaries are semantically distinct from visual groups and support explicit parent control.
- [ ] Undo/Redo covers the current editing session and stale-save conflicts preserve the local draft for explicit resolution.
- [ ] Connections show direction clearly and support a short communication or data intent label.
- [ ] Selecting a Finding can focus cited Canvas evidence and provide a return path to the Review.
- [ ] A semantic Component and Connection outline stays synchronized with the visual Canvas.
- [ ] The property editor and outline expose the same important information as the visual Canvas for screen-reader and non-pointer Users.
- [ ] Focus, selection, contrast, zoom, pan, grouping, and connection states remain understandable without color alone.
